# ManglePDF — Finish Condition
**Prompt 2 of 2 · "The Gauntlet"**

> Companion document: `GOAL.md` (the Charter) defines the terms, priorities ([P0]/[P1]/[P2]) and constraints used here. Read both before writing code.

---

## 0. Purpose and the one rule

This document defines what **done** means. ManglePDF is done when — and only when — a clean checkout passes every gate below and produces an **Evidence Pack** that a skeptical stranger could audit. Effort, argument, and a long feature list are not evidence.

**The one rule: no self-certification.** Never claim completion from memory, from a green unit-test run, or because the code "should work". Completion means a complete, contiguous, passing run of `cargo xtask gauntlet`, plus the GUI run, plus the Evidence Pack, **replayed and confirmed by an independent verifier** — a fresh session with no access to your notes beyond the repo, or the human.

**Roles.** The **Builder** (you, working through the Charter) uses this document as a compass from day one and designs against it. The **Verifier** runs it adversarially: their job is to try to prove the software is *not* done.

**Vocabulary.** An unmarked check is a **MUST-check** (failure fails its gate). **(S)** marks a SHOULD-check (counts toward a threshold). **[H]** = headless/automated. **[G]** = performed through the real GUI by computer-use (real mouse and keyboard, real screenshots). **[H+G]** = both. A **chain checkpoint** is a stage's output file, which becomes the next stage's input. The **hero doc** is `TravelGuide.pdf` (F31).

## 1. Run rules

- **Clean room.** Fresh clone at a recorded commit; `cargo clean`; `--locked`; empty temp and work directories; `--reset-prefs`. The run needs no network (download corpora beforehand).
- **Environment record.** `env.json` captures OS, CPU, RAM, GPU, screen size/scale, toolchain, commit hash, and seed.
- **Reference hardware** for performance: 8 logical cores, 16 GB RAM, SSD, integrated GPU. On weaker hardware the verifier may relax *time* thresholds by at most 2× and must record why. Memory and correctness thresholds never relax.
- **Seeds.** `cargo xtask gauntlet --seed N`; fuzzing, soak, and random selections derive from the seed. The verifier picks N.
- **Chain.** Stages S1–S10 run in order; each consumes the previous checkpoint unless it says "fresh copy". If a stage fails, stop, fix the root cause, add a regression test, and **rerun everything from S0**. The official pass is one contiguous run.
- **Anti-gaming — any violation voids the run:**
  - No special-casing fixtures (by name, hash, size, or content) and no test-only behaviour in product paths (`cfg(test)` differences, env-var toggles, feature flags that change behaviour under test).
  - No loosening thresholds, fixtures, or expected values after the first full run without an ADR, human approval, and a fresh full run.
  - Goldens must be reviewed with vision (and an independent oracle where possible) before blessing; a golden generated by the code under test is not evidence.
  - GUI evidence must come from the real application window driven by real input events. Screenshots produced any other way don't count.
  - No mocking the parser/renderer/writer in acceptance or UI tests. The product binary contains no fixture data or expected outputs.
  - `#[ignore]`d tests, skipped tests, and disabled checks count as failures — except oracle-absent skips, which must be listed in the report and covered by human-supplied substitutes.
  - Fixtures come from `tools/fixturegen` (which MUST NOT depend on any product crate) or from external sources (wild/held-out).
  - Swallowed errors, blanket `catch_unwind`, and retry loops that hide failures don't count.

## 2. Gate 0 — Policy and hygiene [H] (`cargo xtask policy`) — 100% required

- **G0.1** Every manifest uses edition 2024, `resolver = "3"`; `rust-toolchain.toml` pinned; `Cargo.lock` committed and `--locked` builds succeed.
- **G0.2** Every first-party target (lib, bin, test, bench, example, `build.rs`, xtask, tools) has `#![forbid(unsafe_code)]` and inherits `[workspace.lints]`. An AST scan finds zero `unsafe` tokens and zero `allow(unsafe_code)`.
- **G0.3** The full dependency graph (`cargo metadata`, all kinds) contains no banned crate (Charter §2.3) and no crate whose name/description/keywords/repository indicates PDF provenance, unless `docs/DEPENDENCIES.md` records a provenance justification approved by the human.
- **G0.4** No process spawning in product crates except one audited OS-integration module (reveal in folder, open URL, print spooler); nothing invokes PDF tools.
- **G0.5** `cargo fmt --check`; `cargo clippy --workspace --all-targets -- -D warnings`; `cargo test --workspace` with zero ignored tests; `cargo build --release` with zero warnings.
- **G0.6** Library crates deny `unwrap_used`, `expect_used`, `panic`, `todo`, `unimplemented`, `unreachable`; no `todo!()`/`unimplemented!()` reachable anywhere.
- **G0.7** Every bundled asset (fonts, CMaps, icons, themes) has a permissive-licence entry in `THIRD_PARTY_LICENSES.md`.
- **G0.8** Icons: every icon is an SVG in `assets/icons/`, lint-clean; no raster images used as icons; the verifier reviews the icon gallery sheet and confirms they are hand-authored (no traces of cropping or auto-tracing from the mockup).
- **G0.9** Docs exist and are current: `README.md`, `ARCHITECTURE`, `STATUS`, `DEPENDENCIES`, `PDF-QUIRKS`, `TESTING`, `ICONS`.
- **G0.10** `cargo xtask fixtures --seed N` regenerates every Tier-A fixture byte-identically; `tools/fixturegen` has no dependency on any `mangle-*` crate.

## 3. Gate 1 — Fixtures and corpus

**Tiers.** **A** = generated by `tools/fixturegen` (deterministic, checked in when small). **B** = ≥ 40 diverse real-world PDFs (LaTeX papers, InDesign/Illustrator output, Word/Office exports, scans, government forms, maps, CAD plots, presentations, broken files), fetched from public corpora if the network allows, otherwise supplied by the human; kept in `corpus/wild/` with `SOURCES.md` and licences. **C** = ≥ 3 **held-out** PDFs the human drops into `corpus/heldout/` at the very end (see Gate 9).

For codecs where writing an encoder is impractical (JPX, complex JBIG2, progressive JPEG), fixtures may come from wild corpora or independent encoders (cjpeg, opj_compress, jbig2enc, ImageMagick, Ghostscript). If none is available, the human MUST supply at least one JPX and one JBIG2 PDF before acceptance.

`fixtures/MANIFEST.toml` records, per fixture: features, page count, expected per-page text, object counts, font list, annotation/field inventories, secrets (F33), and SHA-256. Fixturegen output is validated with any independent tools present (qpdf/mutool/pdfinfo) to prove intentional validity or intentional breakage.

## 4. Gate 2 — Robustness [H]

- **G2.1 Open–render–save matrix.** For every Tier-A and Tier-B file: open; render all pages (cap 200 for scale files) at 72 and 200 DPI; extract text; **full save → reopen** and compare page count, normalised text, and render (SSIM ≥ 0.999 or ≤ 1 LSB); a **no-op incremental save** leaves the original bytes as an exact prefix. No panic; no hang > 60 s per file (scale fixtures use Gate 7 caps); peak RSS within caps.
- **G2.2 Recovery.** F06–F09 open with a "repaired in memory" banner and render ≥ 95% of expected content; F07 shows every recoverable page plus a clear message; saving a repaired file forces a full rewrite.
- **G2.3 Mutation fuzz.** ≥ 200,000 mutated documents (byte flips, splices, truncation, structure-aware key/number/reference mutation) over ≥ 25 seed files, each under a 5 s watchdog and a 2 GB cap: **0 panics, 0 hangs, 0 OOMs.** Every historical crash lives in `tests/regressions/` and passes.
- **G2.4 Limits.** Decompression bomb, 200-deep nesting, self-references, and `/Prev`/`/Parent` loops terminate gracefully within 2 s with a diagnostic.
- **G2.5 Crash safety.** `kill -9` during full save and during incremental save at ≥ 20 random points each: the target is always the complete old file or the complete new file, and autosave recovery restores the last committed edit at next launch (≤ 30 s of work lost).
- **G2.6 I/O errors.** Read-only files, read-only directories, disk-full simulation, and vanished files are reported without data loss.

## 5. Gate 3 — Render fidelity [H]

- **G3.1 Oracle comparison.** Needs ≥ 1 independent renderer on the machine (else human-supplied reference PNGs for F12–F22 and F31). At 150 DPI: per-page best-of-oracles SSIM ≥ 0.95; median ≥ 0.985 across F12–F22, F31, and Tier B; ≤ 3% of pages below 0.95, each documented in `docs/known-diffs.md` with root cause and evidence.
- **G3.2 Analytic checks (oracle-free).** Fixturegen emits companion expectations computed by formula for flat colours and simple geometry: all 16 blend modes, axial/radial gradient sample points, Lab/CalRGB conversions, alpha compositing, soft-mask luminosity. Deviation ≤ 2/255 per channel.
- **G3.3 Text extraction vs oracle** (pdftotext/mutool if present): word-level F1 ≥ 0.99 on text fixtures.
- **G3.4 Invariants.** Tile-stitched render is bit-identical to whole-page render at 5 zoom levels; 1-thread and N-thread renders are identical; `/Rotate 90` equals the rotated `/Rotate 0` render (±1 LSB); parse → serialize → render of every content stream is pixel-identical.
- **G3.5 Vision spot-check.** The verifier compares 30 randomly chosen pages against oracle renders and finds no missing content, tofu glyphs, colour inversions, or clipped regions.

## 6. Gate 4 — THE GAUNTLET (chained end-to-end scenario)

**Story.** You are the production editor of a travel publisher. `TravelGuide.pdf` arrived from a design pipeline and has since been touched by three other tools. You must correct it, add and annotate content, fill and prepare forms, reorganize and merge pages, flatten reviewer comments, redact a confidential brief, protect and sign the result, optimize it, and ship a final file that every other viewer opens perfectly — without disturbing anything you didn't mean to touch.

**Universal assertions** (apply to every edit check unless stated):
- **U1 Locality** — bytes of content streams/resources outside the edit's provenance ranges are unchanged (except required balancing), and pixels outside the edit's bounds (dilated 2 px) are identical between before/after renders.
- **U2 Validity** — after every save the built-in validator passes (balanced `q/Q`, `BT/ET`, `BDC/EMC`; no dangling references; resources complete; xref consistent) and Gate 6 validators pass.
- **U3 Reversibility** — undo yields structurally identical content; redo returns the edited state.
- **U4 Honesty** — every limitation met is surfaced in the UI (banner/notice), confirmed in [G] runs.
- **U5 Evidence** — each check appends a record to `checks.jsonl` (measured values, thresholds, evidence paths, before/after/diff renders, file hashes).

## 7. Gate 5 — GUI run protocol [G]

Every [G] and [H+G] check is executed through the **real GUI** by the Builder and **again by the Verifier** (at least a seed-chosen half). The Builder authors `docs/acceptance/GUI-SCRIPT.md` from this document's [G] rows; the Verifier may follow it verbatim.

- **Launch:** `manglepdf --window-size 1536x1024 --scale 1 --theme light --reset-prefs`. Repeat the S1–S2 [G] checks at `--scale 2` and at a 1024×700 window.
- **Per step:** (1) screenshot before; (2) act with real mouse/keyboard — **no automation API**; (3) screenshot after; (4) look at the screenshot and write a one-line observation of what is actually visible (panel values, selection box, notices); (5) save as `gui/<check-id>-<n>.png` and append the observation to `gui-log.md`; (6) record elapsed time.
- **File dialogs:** use the GUI file dialog for S0.1 and S9.1; other opens may use drag-and-drop or `--open`.
- **Responsiveness:** log any interval where the UI doesn't respond for > 2 s; > 5 s fails the check.
- **Audit:** the Verifier re-inspects ≥ 25 random screenshots against the log. A fabricated or wrong observation voids the run.

## 8. Gate 6 — Interoperability [H+G]

- **G6.1 Independent engines.** At least **two different PDF engines** from: PDFium (Chrome/Edge), PDF.js (Firefox), PDFKit (Preview/Safari), poppler (Evince/Okular/pdftoppm), MuPDF (mutool), Ghostscript, Adobe Reader. If fewer than two are installed, install them (network permitting) or ask the human.
- **G6.2 Visual equivalence.** Every chain checkpoint (after S1…S10, plus FINAL) opens in ≥ 2 engines; on every page touched, computer-use screenshots (or CLI renders for CLI-capable engines) are judged visually equivalent to our render — no missing content or annotations, wrong fonts, or shifted objects. Record per page in `interop/`.
- **G6.3 Behaviour in another viewer.** A checkbox and a text field we saved can be toggled/filled; a link click navigates; popup comments show; bookmarks and page labels display; the layer panel toggles OCGs; the watermark layer toggles.
- **G6.4 Structural validators** (whichever exist): `qpdf --check` (no errors; warnings only from a recorded allow-list), `mutool clean`/`draw` (no error output), `pdfinfo`/`pdffonts` (embedding status matches manifest), pikepdf/pypdf open — plus our own strict validator.
- **G6.5 Independent checks** of redaction leaks (independent text extraction) and signatures (pdfsig/openssl/viewer) wherever tools exist.
- **G6.6 Untouched-object guarantee.** For each checkpoint, compare parsed objects of the original vs the output: objects not intentionally edited are byte-identical (incremental) or semantically equal (full rewrite).

## 11. Gate 9 — Held-out trial and adversarial session

**G9.1 Held-out trial [G].** At least 3 PDFs unseen by the Builder — supplied by the human in `corpus/heldout/`, or (if none) chosen by the Verifier's seed from Tier B files the Builder never opened (recorded). Suggested mix: a LaTeX paper (Type 1/Type 3), an InDesign brochure (transparency + CMYK/ICC), a scanned document (JBIG2/CCITT), a Word-exported tagged form, a large vector map or CAD plot, and a damaged file. For each: open; render all pages; then through the GUI perform 3 text edits (one needing a new glyph), 2 image edits (move + replace), 1 shape edit, 3 annotation types, flatten, one redaction with a leak scan, save, and open in ≥ 2 other viewers.
**Pass:** ≥ 90% of individual actions succeed on the first attempt; zero corruption, data loss, or crash; every failed action is honestly reported in the UI (U4).

**G9.2 Adversarial session.** 45 minutes of free-form testing by a fresh Verifier trying to corrupt files, hang the UI, lose edits, or produce invalid output: edit → undo → redo → save → rotate sequences; huge paste; rapid zoom during render; cancel mid-save; drag in unsupported files; missing fonts; permission-restricted and signed documents; rapid tab/panel switching.

**Severity.** **S1** = data loss, corrupted output, crash, UI hang > 5 s, silent content loss, redaction leak, or signature invalidation without warning. **S2** = wrong result of a P0 feature, visible render error on P0 content, invalid-but-openable output, missing P0 UI. **S3** = cosmetic or non-P0. Any S1 found resets the run (fix, then full rerun). Log all bugs in `docs/BUGS.md`; none open at S1 or S2 at acceptance.

## 12. Scoring and pass rule

**PASS requires all of the following:**
- Gate 0: 100%. Gates 1, 2, 3: every check met.
- Gate 4: **100% of MUST-checks** and ≥ 75% of (S)-checks, with no failure involving data loss.
- Gate 5: every [G]/[H+G] check executed through the GUI at 1×; the S1–S2 subset also at 2× and at 1024×700; observations audited.
- Gate 6: every checkpoint validated by ≥ 2 engines with zero validator errors.
- Gate 7: all thresholds, soak clean, determinism confirmed.
- Gate 8: ≥ 90/100 with the stated constraints.
- Gate 9: held-out ≥ 90% with zero corruption; the adversarial session leaves no open S1/S2.
- **Two consecutive clean full runs** from clean checkouts with different seeds — the second performed by the independent Verifier.
- `docs/BUGS.md` has no open S1/S2; `docs/known-diffs.md` and `docs/design/deviations.md` are reviewed by the human.

A pass with waivers is **not** a pass; any waiver needs the human's explicit written approval, recorded in the report.

## 13. Failure protocol

1. Record the failure in `docs/acceptance/FAILURES.md` (check ID, symptom, evidence).
2. Find the **root cause**, fix it in product code, add a regression test at the lowest practical level (plus a fixture if the case is new).
3. Re-run the affected check and its neighbours, then the **entire** Gauntlet from S0.
4. Never edit fixtures, thresholds, or expected values to make a check pass. If you believe a check is wrong, write an ADR with evidence and ask the human.
5. After three failed approaches, document them in `STATUS.md`, then take the simpler design or ask the human. Never declare partial success as success.
