# PDF quirks

Facts that are true of the format and not of the documentation's happy path. Each one
is written down because implementing it differently means a wrong answer in the
product, and each has a test.

## Syntax

**A `>` that is not `>>` is legal garbage.** So is a stray `)`. Real files contain both
after damage. They are skipped rather than treated as a terminator, and a file made
entirely of them must not recurse the lexer to death.

**`--5` and `+.5` appear in the wild.** A double sign is damage, not a number.

**`6.02e23` and `1e3` are legal.** The integer/real distinction matters: `1e3` is a real,
and writing it back as `1000` changes the object.

**Hex strings and literal strings are different bytes.** `<48656C6C6F>` and `(Hello)`
hold the same value but are not the same token. A lossless writer keeps the spelling.

**`/Length` lies.** It is wrong often enough that it must be a hint: the parser accepts
it only when `endstream` actually follows, and otherwise scans for it.

**`stream` may be followed by `\r\n`, `\n` or `\r`.** A space between the keyword and
the newline does not occur in a valid file but does in a damaged one.

**Junk after `%%EOF` is common.** Linearised files in particular carry a first revision
whose `startxref` is *not* at the end of the file, so the last `startxref` before the
last `%%EOF` is not always the right one.

## Cross-references

**A `/Prev` loop is a real file, not a theoretical one.** Generated by tools that
concatenate revisions badly. Walking it must terminate with a note.

**`/XRefStm` sits beside `/Prev` in hybrid files, and `/Prev` wins.** The classic table
is authoritative; the stream only covers objects the table omits.

**Object number 0 is free and always present.** Files whose numbering has holes produce
malformed xref sections if you write only the live objects.

**The trailer's `/Root` may point at nothing.** The only reliable fallback is to find
the object with `/Type /Catalog`.

## Filters

**`/FlateDecode` means zlib, not deflate.** The data is a two-byte header, the RFC 1951
stream, and a four-byte Adler-32 of the *uncompressed* input. Writing the bare deflate
stream under that filter name produces a file that reads back in the writer's own decoder
and in no other program, which is why no round trip catches it: every round trip inflates
our output with our own reader. `mutool` calls it `zlib error: unknown compression method`.

**A zlib header is `CMF` and `FLG`, and `CMF * 256 + FLG` must be a multiple of 31.** The
method is the low nibble of `CMF` — 8 for deflate — and its high nibble is the window size
as `log2(bytes) - 8`, so 7 is the 32 KiB window PDF requires. `FLG` carries the level, a
dictionary flag, and a check value that makes the pair divisible by 31; because 256 is
`8*31 + 8`, that check fails on a byte-swapped or misaligned header and costs one modulo.

**A zlib stream with no wrapper is common enough to decode anyway.** Some producers write
bare deflate under `/FlateDecode`, and so did this project until it did not. Decoding both
forms is the right answer; a reader that insists on the wrapper loses a page, and one that
strips two bytes on sight loses it the other way.

**Flate has a hard expansion ceiling of about 1032:1.** A match returns at most 258
bytes for a few bits of code. A ratio cap above that cannot bite a real file, which is
why `MAX_EXPANSION_RATIO` is 1200 rather than 10.

**Truncated Flate must return a prefix.** The tail of a damaged file is usually the
part that was being written when something went wrong, and it is often the whole page.
An error here loses the document.

**LZW has two incompatible variants.** `/EarlyChange 0` (late change) grows the code
width one code later than `/EarlyChange 1` (the default). Getting this wrong decodes
high-bit text as noise for the second half of the file.

**A PNG predictor's byte stride is `ceil(colors × bits / 8)`, not `colors × ceil(bits / 8)`.**
For 1-bit RGB the first is 1 and the second is 3. Every sub-byte multi-component image
decodes wrongly under the second.

**Predictors are applied after the filter, once.** A `/Predictor` in `/DecodeParms`
applies to the output of the filter named in the same `/DecodeParms` entry, not to the
output of the whole chain.

**A damaged PNG row filter must not discard the rows before it.** Every other decoder
here returns partial output; the predictor used to be the exception.

**ASCII85's optional `<~` is two characters.** Consuming only the `<` makes the `~`
look like the terminator, and the stream decodes to nothing while claiming success.

**A bare `~` is not the `~>` terminator.**

**CCITT damage is counted per row, twice, in the reference implementations.** The
`/DamagedRowsBeforeError` budget is a limit, not a suggestion; a decoder that gives up
early shows blank rows where the original had text.

**`/K 0` is Group 3 2-D, not Group 3 1-D.** They are different encodings.

## Encryption

**`/P` bit 1 and 2 (from the most significant) are reserved, and bits 13-32 are
undefined.** A document with "no restrictions" writes `-1` or `-4`; both are correct.
Deciding "restricted" by testing every non-reserved bit marks ordinary unrestricted
files as restricted.

**`/Encrypt` and `/ID` are stored in the clear.** They are inside the encryption
dictionary and inside the trailer precisely so that they can be read before any key
exists. Decrypting them corrupts the key derivation.

**`/Identity` crypt filter means the object is not encrypted at all**, and the presence
of `/Encrypt` in the file says nothing about whether a given object is covered. `/StmF`
and `/StrF` decide it per object.

**`/V 4` with AESV2 usually has no `/SubFilter`.** The algorithm comes from `/CF`, and
a decoder that only looks at `/SubFilter` will use RC4 on AES data.

**R5 and R6 differ from R2-R4 in more than key size.** R5 and above put the file key in
`/UE` and `/OE`, encrypted with a key derived by a different algorithm, and put the
permissions in a `/Perms` string whose own structure has to be validated.

**`/EncryptMetadata false` means `/Type /Metadata` streams are not encrypted.** They are
XMP, and are routinely left readable so that indexers can read them.

**R6 passwords are normalised (SASLprep) before hashing; R2-R4 passwords are not.**
Truncation to 32 bytes and the standard padding apply only to R2-R4.

## Documents

**A page tree can contain a `/Kids` entry that is not a page, a `/Count` that is wrong,
and a cycle.** All three occur. Depth and cycle limits are not optional.

**Inherited attributes are not optional either.** `/Resources`, `/MediaBox`, `/CropBox`
and `/Rotate` come from ancestors, and a page that omits them is normal.

**"Normal" is not one thing.** `(1 0 obj` on its own line is the common form, but
`1 0 obj` with no space, `\r\n` endings, and objects with leading junk before the header
all appear.

**A page's `/Contents` may be one stream or an array of streams**, and the array is
concatenated with whitespace between the parts. A file that treats it as always-array
loses content.

**Annotations live in `/Annots` and draw above page content**, in array order, always.
Reordering page content does not reorder them.
